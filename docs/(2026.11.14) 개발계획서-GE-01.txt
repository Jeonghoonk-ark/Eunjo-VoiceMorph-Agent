# Ⅰ. 프로젝트 개요

## 1. 추진 배경

개인이 음성·영상 콘텐츠를 제작할 때는 대본 작성, 녹음, 음성 편집, 음색 조정, 배경음악 구성 등 여러 작업이 필요하다.

특히 캐릭터 영상이나 교육 콘텐츠에서는 서로 다른 등장인물의 목소리를 표현해야 하는 경우가 많다.

기존 TTS 서비스는 텍스트를 입력하면 음성을 생성할 수 있지만, 사용자가 직접 녹음한 대사의 억양, 연기, 감정적 표현을 그대로 살리기에는 한계가 있다.

예를 들어 사용자가 같은 문장을 다음과 같이 녹음했다고 가정한다.

- 기쁜 마음으로 말하는 대사
- 놀라서 속삭이는 대사
- 슬픈 감정을 억누르는 대사
- 장난스럽게 웃으며 말하는 대사

문장은 동일하더라도 발화 리듬과 감정 표현은 다르다.

EUNJO VoiceMorph Agent는 **사용자가 직접 수행한 음성 연기를 유지하면서, 허가된 AI 캐릭터의 음색으로 변환하는 창작 도구**를 목표로 한다.

## 2. 핵심 목표

1. 한국어 녹음 및 오디오 파일 입력
2. 발화 내용과 운율 특성 분석
3. 허가된 캐릭터 음색 선택
4. Speech-to-Speech 음색 변환
5. 원본의 억양·강조·발화 간격 최대 보존
6. 음질과 발화 내용 자동 검증
7. 사용자 미리 듣기 및 부분 재생성
8. WAV·MP3 출력
9. 캐릭터 음색의 사용권·동의 관리
10. 로컬 및 내부망 환경 지원

## 3. 서비스 정의

**"내가 연기하고, AI가 캐릭터의 목소리로 표현한다."**

서비스가 생성하는 것은 단순한 음성 파일이 아니라 사용자 연기와 캐릭터 음색을 결합한 오디오 콘텐츠이다.

## 4. 초기 대상 사용자

| 사용자 | 활용 목적 |
|---|---|
| 개인 콘텐츠 제작자 | 캐릭터 영상 및 내레이션 |
| 웹툰·애니메이션 제작자 | 등장인물 대사 제작 |
| 교육 콘텐츠 제작자 | 여러 역할의 설명 음성 |
| 게임 개발자 | NPC 및 캐릭터 대사 |
| 사내 교육 담당자 | 시연·안내 콘텐츠 |
| 음성 연구자 | 변환 품질 실험 |

## 5. 서비스 원칙

- 입력 음성은 사용자가 직접 녹음했거나 적법한 사용 권한을 확보한 음성으로 제한한다.
- 대상 음색은 합성 캐릭터 음색 또는 명시적 사용 동의가 확인된 음색만 허용한다.
- 실제 인물의 무단 음성 복제 및 사칭 용도는 지원하지 않는다.
- 원본 음성과 생성 음성의 저장·삭제 정책을 제공한다.
- 음성 변환 결과가 AI로 제작되었다는 이력을 관리한다.
- 감정·억양 보존은 목표 기능이며 완벽한 재현을 보장하지 않는다.

이번에는 기쁨에 찬 목소리다.

그러나 문장 사이의 침묵, 감정의 흐름, 말끝의 떨림은 원래의 연기를 따라간다.

화면 중앙에 문구가 나타난다.

## 2. 대표 시나리오 A — 캐릭터 영상 제작

**상황**

사용자가 직접 녹음한 한국어 대사를 애니메이션 캐릭터 음색으로 변환한다.

**흐름**

1. 새 음성 프로젝트 생성
2. 마이크로 한국어 대사 녹음
3. 원본 음성 재생
4. 사용 가능한 캐릭터 음색 선택
5. 음색 사용권 확인
6. 변환 강도 및 음높이 옵션 조정
7. 변환 실행
8. 원본·변환 음성 비교
9. 발음 및 음질 검증
10. 특정 구간 재변환
11. 최종 결과 WAV/MP3 출력

**결과**

원본 대사의 타이밍과 감정적 특징을 최대한 반영한 캐릭터 음성 파일이 생성된다.

## 3. 대표 시나리오 B — 여러 캐릭터 제작

사용자가 하나의 대본에 등장하는 3개 캐릭터를 직접 연기한다.

각 대사는 별도의 음성 세그먼트로 관리한다.

시스템은 세그먼트별로 다른 허가된 캐릭터 음색을 적용한다.

최종적으로 다음 산출물을 제공한다.

- 캐릭터별 개별 WAV
- 대사 순서에 따른 합성 오디오
- 세그먼트별 시간정보
- 변환 설정 파일
- 편집 프로그램용 파일 패키지

## 4. 대표 시나리오 C — 교육용 내레이션

사용자가 설명 음성을 녹음한다.

시스템은 승인된 AI 안내자 음색으로 변환한다.

교육용 영상에 활용할 수 있도록 일정한 음량과 안정적인 음질로 내보낸다.

단, 공공기관의 공식 안내 음성처럼 오인될 가능성이 있는 사용은 별도 승인 및 표시 정책을 적용한다.

```python
class VoiceConversionProvider:
    def load_model(self, model_id: str):
        ...

    def convert(self, input_audio, config):
        ...

    def get_capabilities(self):
        ...

    def unload_model(self):
        ...
```

실제 구현에서는 타입 정의, 예외 처리, 리소스 해제 및 모델 캐시 관리 등을 추가한다.

# Ⅴ. Voice Conversion 모델 전략

## 1. 모델 선택 기준

- 한국어 발음 보존 능력
- 원본 운율 보존
- 감정 표현 보존
- 캐릭터 음색의 일관성
- CPU 실행 가능 여부
- 모델 크기 및 메모리 사용량
- 추론 시간
- 모델 라이선스
- 참조 음색의 사용권
- 오프라인 운영 가능 여부

## 2. RVC 기반 변환

RVC는 사전 준비된 대상 음색 모델을 사용하여 원본 발화를 다른 음색으로 변환하는 방식이다.

일반적인 구성 요소는 다음과 같다.

- 음성 콘텐츠 특징 추출
- F0 추출
- 대상 음색 모델
- 필요시 특징 검색 인덱스
- 파형 합성

초기 프로젝트에서는 이미 사용권이 확인된 음색 모델을 이용한다.

사용자 고유 캐릭터 음색 학습은 후속 단계에서 별도 실험한다.

## 3. OpenVoice V2 비교 실험

OpenVoice V2는 음색 복제 및 음성 스타일 관련 기능을 제공하므로 비교 후보로 유지한다.

다만 활용 방식에 따라 중간 TTS 생성이 필요하거나 원본 운율이 달라질 수 있다.

따라서 원본 발화가 얼마나 보존되는지 실제 한국어 테스트 데이터로 측정해야 한다.

## 4. Seed-VC 연구 후보

짧은 참조 음성으로 대상 음색을 지정하는 Zero-shot VC 방식의 비교 실험에 활용할 수 있다.

단, GPL-3.0 라이선스와 저장소 유지관리 상태를 고려하여 초기 제품의 필수 의존성으로 채택하지 않는다.

## 5. 모델 선택 구조

```text
Voice Conversion Request
        ↓
Model Registry
        ↓
License & Consent Check
        ↓
Capability Check
        ↓
Runtime Selection
   ├─ CPU
   ├─ GPU
   └─ Optional Remote
        ↓
Conversion Provider
```

추론 실행 전 모델 로딩 성공 여부, 자원 요구량, 라이선스 상태를 확인한다.

## 6. 모델 메타데이터

```json
{
  "model_id": "CHARACTER-001",
  "model_type": "RVC",
  "model_version": "1.0",
  "voice_name": "Eunjo Original Character A",
  "language": ["ko"],
  "license_status": "VERIFIED",
  "commercial_use_allowed": false,
  "consent_status": "APPROVED",
  "approved_uses": ["PRIVATE_DEMO"],
  "runtime": ["CPU"],
  "model_file_hash": "sha256:example",
  "status": "ACTIVE"
}
```

이 예시는 스키마 설명용이며 실제 모델의 사용권이나 성능을 의미하지 않는다.

# Ⅵ. CPU 및 GPU 운영 전략

## 1. CPU-only POC

GPU가 없는 환경에서도 다음 작업을 수행한다.

- 음성 업로드 및 재생
- 리샘플링
- 채널 변환
- 음성 구간 탐지
- 파형 시각화
- 음량 분석
- 기본 노이즈 처리
- 구간 분할 및 병합
- WAV/MP3 변환
- 변환 설정 관리
- 가능한 모델의 CPU 추론

음색 변환 자체도 CPU 실행을 우선 검증하지만 처리속도와 품질을 보장하지 않는다.

## 2. CPU 변환 실행 방법

1. 작은 모델 또는 검증된 사전학습 모델 사용
2. 짧은 음성 구간부터 실행
3. 가능한 경우 ONNX Runtime 사용
4. 모델 로딩 캐시
5. 입력 길이 제한
6. 구간별 처리
7. 필요시 처리 후 병합

단, 모델마다 필요한 F0 및 특징 추출기의 CPU 성능이 다르므로 전체 파이프라인 기준으로 측정해야 한다.

## 3. GPU 권장 구간

- 고품질 대량 음색 변환
- 실시간 음성 변환
- 대용량 모델 추론
- 사용자 전용 음색 모델 학습
- 다중 변환 작업 병렬 실행
- 신경망 기반 고품질 오디오 복원

GPU가 없다는 이유로 작업이 불가능하다고 단정하지 않되, 처리시간이 지나치게 긴 경우 GPU가 필요한 작업으로 분류한다.

## 4. 추론 자원 정책

CPU 모드에서는 기본적으로 동시 모델 추론 작업 1개를 권장한다.

작업 큐에 대기 중인 요청은 순서대로 실행한다.

GPU 모드에서는 VRAM과 모델별 메모리 사용량에 따라 동시 실행 수를 제한한다.

## 5. CPU/GPU 벤치마크

테스트 입력:

- 5초
- 15초
- 30초
- 60초

측정 항목:

- 모델 초기 로딩 시간
- 음성 전처리 시간
- 특징 추출 시간
- 음색 변환 시간
- 후처리 시간
- 총 실행 시간
- 최대 RAM/VRAM
- 결과 음성의 품질

**RTF(Real-Time Factor) = 전체 처리시간 / 출력 음성 길이**

RTF가 1보다 작으면 해당 테스트 조건에서 오디오 길이보다 빠르게 처리한 것이다.

실시간 마이크 변환 가능 여부는 RTF 외에 알고리즘 지연, 버퍼링, 장치 입출력 지연을 별도로 측정한다.

# Ⅶ. 음성 입력 및 전처리 설계

## 1. 입력 포맷

| 포맷 | 입력 | 출력 |
|---|---|---|
| WAV | 지원 | 지원 |
| MP3 | 지원 | 지원 |
| FLAC | 지원 | 선택 |
| OGG | 선택 | 선택 |
| M4A | 선택 | 선택 |

초기 POC는 WAV/MP3를 필수 지원한다.

## 2. 녹음

웹 브라우저에서 마이크 접근 권한을 요청한다.

사용자가 녹음 시작 및 중지를 명시적으로 제어한다.

기능:

- 마이크 선택
- 입력 레벨 표시
- 녹음 시작·정지
- 녹음 시간 표시
- 원본 재생
- 재녹음
- 로컬 임시 저장

## 3. 내부 오디오 포맷

입력 자료는 원본을 보존하고 모델 요구조건에 따라 변환한다.

예시 내부 포맷:

- PCM WAV
- Mono
- Float32 처리
- 엔진별 지정 샘플링 주파수

22,050Hz, 32kHz, 40kHz, 48kHz 등 요구 조건은 선택한 모델에 맞춘다.

전체 시스템이 하나의 샘플링 주파수만 지원하도록 고정하지 않는다.

## 4. 음성 전처리

처리 단계:

1. 입력 파일 검사
2. 오디오 디코딩
3. 채널 분리 또는 모노 변환
4. 무음 구간 감지
5. 음성 구간 추출
6. 입력 레벨 검사
7. Clipping 검사
8. 잡음 수준 추정
9. 필요시 노이즈 감소
10. 모델 입력형식 변환

전처리는 선택적으로 적용할 수 있어야 한다.

과도한 노이즈 제거가 웃음, 숨소리, 속삭임 등 표현 정보를 제거하지 않도록 주의한다.

## 5. VAD

Voice Activity Detection을 사용하여 음성 구간을 식별한다.

구현 후보:

- WebRTC VAD
- Silero VAD
- 에너지 기반 VAD

POC에서는 가벼운 CPU 기반 VAD를 우선 사용한다.

## 6. 세그먼트 처리

긴 음성은 문장 또는 호흡 구간을 기준으로 분할한다.

세그먼트 속성:

- 시작 시간
- 종료 시간
- 음성 길이
- 무음 구간
- 처리 상태
- 변환 모델
- 출력 파일
- 음질검증 결과

세그먼트 경계에서 소리가 끊어지지 않도록 적절한 겹침 처리와 크로스페이드를 지원한다.

# Ⅷ. Speech-to-Speech 변환 엔진

## 1. 처리 흐름

```text
Original Korean Speech
        ↓
Audio Inspection
        ↓
Preprocessing
        ↓
Speech Content Features
        +
Pitch / Prosody Features
        +
Authorized Target Voice
        ↓
Voice Conversion Model
        ↓
Waveform Synthesis
        ↓
Audio Postprocessing
        ↓
Converted Speech
```

## 2. 원본 발화 보존 대상

- 발화 내용
- 전체 발화 길이
- 문장별 구간
- 쉼과 침묵
- 말의 강약
- 음높이 변화 경향
- 강조 위치
- 감정적 표현

모델 특성상 이 항목을 모두 독립적으로 제어할 수 있는 것은 아니다.

지원되지 않는 세부 제어는 UI에서 비활성화하거나 실험적 기능으로 표시한다.

## 3. 변환 설정

| 설정 | 설명 |
|---|---|
| Target Voice | 대상 캐릭터 음색 |
| Pitch Shift | 필요시 음높이 조정 |
| Retrieval Ratio | RVC 인덱스 활용 정도 |
| Protect Setting | 일부 발화 특성 보호 관련 옵션 |
| Noise Reduction | 전처리 강도 |
| Output Gain | 출력 음량 |
| Segment Mode | 분할 처리 방식 |
| Export Format | 출력 포맷 |

모델마다 지원 설정이 다르므로 Provider가 가능한 옵션을 반환한다.

## 4. 감정 보존

감정은 별도의 단일 수치로 보장할 수 없다.

다음 특성을 중심으로 원본 대비 차이를 측정한다.

- F0 흐름
- 에너지 변화
- 발화 속도
- 강조 구간
- 휴지 구간
- 사용자의 주관적 청취 평가

감정 보존 여부는 자동 점수와 사람의 청취평가를 함께 사용한다.

## 5. 부분 재변환

사용자가 특정 구간만 선택해 다시 변환할 수 있어야 한다.

예:

- 00:12~00:18 구간 선택
- Pitch 설정 수정
- 재변환
- 원본 결과와 비교
- 적용 또는 취소

변경되지 않은 나머지 구간은 기존 변환 결과를 유지한다.

## 6. 모델 오류 처리

- 모델 파일 없음
- 모델 로딩 실패
- 메모리 부족
- 샘플링 주파수 불일치
- F0 추출 실패
- 음성 길이 초과
- 출력 파형 오류
- 변환 중 프로세스 중단

오류 원인과 재시도 가능 여부를 구조화해서 반환한다.

# Ⅸ. 오디오 품질 검증 설계

## 1. 검증 목표

음색이 바뀌었다는 사실만으로 변환 성공을 판정하지 않는다.

실제 콘텐츠로 사용할 수 있는 품질인지 평가한다.

## 2. 음질 검증 계층

### Level 1 — 파일 유효성

- 파일 존재
- 디코딩 가능
- 길이 확인
- 채널·샘플링 주파수
- 무음 파일 여부

### Level 2 — 신호 품질

- Clipping
- Peak
- RMS
- 잡음 수준
- 불연속 구간
- 세그먼트 연결 아티팩트

### Level 3 — 발화 보존

- 원본·출력 음성 인식 결과
- 발화 내용 누락
- 한국어 받침 및 자음 왜곡
- 문장 길이 및 타이밍

### Level 4 — 운율 보존

- F0 윤곽
- 음높이 상대 변화
- 에너지 흐름
- 발화 속도
- 침묵 구간

### Level 5 — 캐릭터 음색 품질

- 대상 음색과의 유사성
- 음색의 일관성
- 자연스러움
- 감정 전달력

## 3. 한국어 발화 정확도

가능한 경우 로컬 ASR을 사용한다.

원본과 변환 결과를 동일한 ASR 엔진으로 분석한다.

평가 항목:

- CER(Character Error Rate)
- 음절 또는 어절 오류
- 주요 명사 누락
- 발화 내용 변형

ASR 자체도 오류를 발생시키므로 텍스트 일치도가 낮다는 이유만으로 음색 변환 실패를 확정하지 않는다.

## 4. 운율 분석

사용 가능한 도구:

- librosa
- Parselmouth
- PyWorld
- 모델별 F0 추출기

F0의 절대값 차이와 상대적 억양 형태를 구분한다.

목표 캐릭터 음역에 맞춰 음높이를 이동한 경우에는 상대적인 F0 윤곽 비교를 사용한다.

## 5. 음질 검증 결과

```json
{
  "job_id": "JOB-001",
  "status": "REVIEW_REQUIRED",
  "metrics": {
    "duration_ratio": 1.02,
    "clipping_detected": false,
    "cer": 0.08,
    "f0_correlation": 0.87,
    "peak_dbfs": -2.1
  },
  "warnings": [
    "일부 받침 발음 청취 검토 필요"
  ]
}
```

수치는 예시이며 실제 모델 성능을 나타내지 않는다.

## 6. 사람이 확인할 항목

사용자에게 다음 질문을 제공한다.

- 대사가 원본과 동일하게 들리는가?
- 말의 감정이 유지되는가?
- 캐릭터 음색이 자연스러운가?
- 잡음이나 금속성 소리가 발생하는가?
- 불필요한 침묵이나 잘림이 발생했는가?

5점 척도로 평가할 수 있도록 한다.

# XIII. 작업 큐 및 비동기 실행

## 1. 목적

음성 변환은 모델 크기와 하드웨어에 따라 실행시간이 길어질 수 있다.

따라서 HTTP 요청을 유지한 상태로 모든 처리를 수행하지 않는다.

## 2. 작업 상태

```text
CREATED
   ↓
VALIDATING
   ↓
QUEUED
   ↓
PREPROCESSING
   ↓
INFERENCING
   ↓
POSTPROCESSING
   ↓
VALIDATING_OUTPUT
   ↓
SUCCEEDED
```

예외 상태:

- `FAILED`
- `CANCELLED`
- `RETRY_PENDING`
- `REVIEW_REQUIRED`

## 3. POC 작업 큐

SQLite 기반 작업 테이블과 독립 Python Worker로 시작한다.

서버가 재시작되어도 작업 상태를 복원할 수 있어야 한다.

추후 다중 Worker 및 대량 처리 단계에서 Redis 기반 작업 큐 등을 검토한다.

## 4. 작업 재시도

- 일시적 파일 접근 오류: 재시도 가능
- 모델 로딩 충돌: 리소스 정리 후 재시도
- 메모리 부족: 자동 무한 반복 금지
- 라이선스 또는 동의 없음: 재시도 불가
- 입력 파일 손상: 사용자 보완 요청

재시도 횟수 및 실패 사유를 기록한다.

## 5. 작업 취소

사용자가 작업 취소를 요청하면 안전한 중단 지점에서 처리한다.

중단 시 모델 리소스와 임시 파일을 정리한다.

# XIV. 개인정보·동의 및 권리관리

## 1. 기본 정책

음성은 개인의 식별 가능성을 가진 정보가 될 수 있으므로 민감한 자료로 취급한다.

입력 음성과 대상 음색 모두 적절한 사용 권한을 확인한다.

특히 대상 음색의 소유자와 콘텐츠 이용 목적을 관리한다.

## 2. 입력 음성 동의

사용자가 직접 녹음하는 경우에도 녹음·저장·변환·보존 범위를 명확하게 안내한다.

타인 음성이 포함된 파일은 해당 사람의 동의 또는 적법한 권한을 확인해야 한다.

## 3. 대상 음색 동의

관리 항목:

- 음색 제공자 또는 권리자
- 사용 동의일
- 허용 사용 목적
- 상업적 사용 여부
- 공개 배포 허용 여부
- 동의 만료일
- 동의 철회 여부
- 모델 배포 허용 여부
- 근거 문서

## 4. 동의 상태

- `PENDING`
- `APPROVED`
- `REJECTED`
- `EXPIRED`
- `REVOKED`

`APPROVED`가 아니거나 요청한 사용 목적이 승인 범위를 벗어나면 변환을 차단한다.

## 5. 저장 정책

- 원본 오디오
- 전처리 파일
- 중간 특징 데이터
- 변환 결과
- 음색 모델
- 품질검증 결과

각 파일 유형별로 보존기간을 따로 관리한다.

예시 운영 기본값:

- 일반 임시 파일: 작업 종료 후 24시간 이내 삭제
- 사용자 프로젝트 파일: 사용자가 명시적으로 저장
- 삭제 요청: 접근 차단 후 보존 정책에 따라 처리
- 감사기록: 최소 필요정보만 보관

보존기간은 실제 서비스 운영 전 개인정보처리방침과 기관 요구사항에 따라 확정한다.

## 6. 오용 방지

- 무단 제3자 음색 등록 차단
- 유명인·실존 인물 사칭 목적 사용 제한
- 권한 없는 공개 배포 제한
- 타인 음성 사용 시 동의 증빙
- 위험 용도 신고 및 관리자 검토
- AI 생성 음성임을 표시할 수 있는 메타데이터
- 다운로드·공유 이력 관리

법적 요구사항에 따른 AI 생성물 표시 및 개인정보 처리는 정식 서비스 출시 전 별도 검토한다.

### P1 — MVP

- 부분 재변환

### P2 — 서비스 확장

- GPU 가속
- 다중 사용자
- 사용자 음색 등록
- 동의관리
- 일괄 변환
- 실시간 변환
- 영상 편집 연동

## 2. 개발 시 필수 원칙

1. 최초에는 실제 변환 가능한 모델 1개만 연결한다.
2. 모델의 라이선스를 검증하지 못하면 사용하지 않는다.
3. 허가된 음색 모델이 없으면 실제 추론 성공을 주장하지 않는다.
4. 더미 데이터와 실제 변환 결과를 구분한다.
5. 원본 음성은 자동 변경하지 않는다.
6. 변환 결과와 모델 설정을 함께 저장한다.
7. AI가 생성한 대체 음성을 원본 녹음으로 표시하지 않는다.
8. CPU 모드에서 실제 처리속도를 측정한다.
9. 모델과 오디오 처리 라이브러리의 버전을 고정한다.
10. GPU가 없어도 데이터 관리·전처리·웹 UI가 동작하도록 한다.
11. 실패한 작업은 오류 사유와 재현 정보를 기록한다.
12. 개인정보 및 음색 사용권 검사를 추론 이전에 실행한다.

## 3. 구현 완료 판정

기능 화면이 존재하는 것만으로 구현 완료라고 판단하지 않는다.

완료 조건은 다음을 모두 충족해야 한다.

- 실제 오디오 입력
- 실제 모델 추론

# XXIII. 향후 확장 방향

EUNJO VoiceMorph Agent는 이후 Eunjo Music Universe와 영상 제작 환경에 연결할 수 있다.

확장 가능한 기능은 다음과 같다.

- 캐릭터별 음색 라이브러리
- 애니메이션 대사 제작
- 게임 NPC 음성 제작
- 교육용 내레이션 생성
- 사용자 연기 기반 음성 콘텐츠 제작
- 자막과 음성 세그먼트 연동
- 영상 편집용 오디오 패키지
- 오디오 생성물 버전관리

특히 사용자가 직접 연기한 음성과 AI 캐릭터 음색을 결합함으로써, 별도의 성우 녹음 없이도 사용자 본인의 표현을 살린 캐릭터 콘텐츠 제작을 지원할 수 있다.

# XXIV. 프로젝트 핵심 선언

EUNJO VoiceMorph Agent의 목적은 사람의 목소리를 무단 복제하는 것이 아니다.

사용자가 직접 녹음한 발화의 의미와 연기를 존중하고, 사용권이 확보된 캐릭터 음색을 활용하여 새로운 창작 표현을 가능하게 하는 것이다.

**"사람이 감정을 연기하고, AI가 새로운 음색을 입히며, 창작자가 결과를 완성한다."**
